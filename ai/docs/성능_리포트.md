- 원시 결과: [`benchmark_results.json`](./benchmark_results.json)

## 3. 정확도 / 성능 (Test Set)

| 지표 | unweighted | weighted |
|------|------------|----------|
| 모델 파일 | `best_risk_model_unweighted.pkl` | `best_risk_model_weighted.pkl` |
| Estimator | LogisticRegression | GradientBoostingClassifier |
| **Accuracy** | **0.7052** | 0.4622 |
| **Balanced Accuracy** | 0.2541 | **0.3584** |
| **Macro F1** | 0.2153 | **0.2601** |
| Weighted F1 | 0.5856 | 0.5086 |

### 클래스별 상세 (unweighted)

| 클래스 | Precision | Recall | F1 | Support |
|--------|-----------|--------|-----|---------|
| 경상사고 | 0.7061 | 0.9987 | 0.8273 | 9,297 |
| 중상사고 | 1.0000 | 0.0013 | 0.0027 | 2,999 |
| 부상신고사고 | 0.3611 | 0.0164 | 0.0313 | 794 |
| 사망사고 | 0.0000 | 0.0000 | 0.0000 | 100 |

→ 거의 전부를 경상사고로 예측해 accuracy는 높지만, 소수 클래스 성능은 매우 낮습니다.

### 클래스별 상세 (weighted)

| 클래스 | Precision | Recall | F1 | Support |
|--------|-----------|--------|-----|---------|
| 경상사고 | 0.7581 | 0.5856 | 0.6608 | 9,297 |
| 중상사고 | 0.2742 | 0.0820 | 0.1263 | 2,999 |
| 부상신고사고 | 0.1535 | 0.4761 | 0.2321 | 794 |
| 사망사고 | 0.0109 | 0.2900 | 0.0211 | 100 |

→ accuracy는 낮지만 balanced accuracy·macro F1·소수 클래스 recall이 상대적으로 높습니다.  
서비스용 위험도(`Σ 확률 × 점수`)에는 **weighted** 사용을 권장합니다.

## 4. 응답 속도 (Latency)

단건 추론 = `predict_proba` 기반 위험도 산출(`predict_risk_score`).  
Warmup 20회 후 **200회** 측정.

| 지표 | unweighted | weighted |
|------|------------|----------|
| mean | **2.25 ms** | 2.87 ms |
| std | 0.36 ms | 0.38 ms |
| p50 | 2.12 ms | 2.76 ms |
| **p95** | **2.98 ms** | **3.60 ms** |
| p99 | 3.64 ms | 4.00 ms |
| min / max | 1.88 / 4.17 ms | 2.37 / 4.59 ms |

### 요약

- 두 모델 모두 **1회 추론이 약 2~4 ms** 수준입니다.
- API 기준 체감 지연은 네트워크·직렬화 오버헤드가 더 클 수 있으나, **모델 순수 추론은 실시간 서빙에 충분**합니다.

## 5. 메모리 (RAM / VRAM)

| 항목 | unweighted | weighted |
|------|------------|----------|
| 모델 파일 크기 | 0.004 MB (≈ 3.8 KB) | **1.45 MB** |
| 로드 전 프로세스 RSS | 153.97 MB | 163.92 MB |
| 로드 후 프로세스 RSS | 157.73 MB | 175.62 MB |
| **로드 시 RSS 증가분** | **+3.76 MB** | **+11.7 MB** |
| 추론 후 RSS | 157.82 MB | 174.65 MB |
| tracemalloc peak (로드) | 2.77 MB | 6.75 MB |
| **GPU VRAM** | **N/A (미사용)** | **N/A (미사용)** |

### 해석

- scikit-learn CPU 모델이므로 **VRAM 사용량은 0**입니다.
- 프로세스 RSS에는 Python·pandas·sklearn 런타임이 포함되어 절대값은 큽니다.  
  **모델 자체 추가 부담은 unweighted ≈ 4 MB, weighted ≈ 12 MB** 수준입니다.
- 서빙 시 프로세스 전체는 대략 **160~180 MB RSS** 범위에서 동작했습니다.

## 6. 종합 결론

| 관점 | 권장 | 근거 |
|------|------|------|
| 서비스 기본 모델 | **weighted** | 소수 클래스·균형 지표 우수 |
| 참고/베이스라인 | unweighted | accuracy만 높음 (다수 클래스 편향) |
| Latency | 둘 다 통과 | mean < 3 ms, p95 < 4 ms |
| 메모리 | 둘 다 경량 | VRAM 불필요, RSS 증가 ≤ 약 12 MB |

### 한계 및 개선 방향

1. 피처 5개만으로는 경중 예측 상한이 낮음 → 피처 확장 필요  
2. 사망·중상 recall이 여전히 낮음 → 데이터·가중치·목표 재정의 검토  
3. accuracy보다 **위험도 오차·calibration·클래스별 recall**을 주 지표로 관리하는 것을 권장
